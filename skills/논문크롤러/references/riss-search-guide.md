# RISS 검색 방법

RISS(학술연구정보서비스, riss.kr)는 공식 Open API가 없다. 검색 결과 페이지 자체를 읽어서
논문 정보를 뽑아야 한다. 로그인 세션에 의존하는 부가기능(원문 다운로드 등)은 필요 없고,
**검색 결과 목록에 보이는 정보(제목·저자·출처·연도·유형·상세 링크)만 있으면 충분**하므로
로그인 없이도 된다.

## 왜 스크립트 대신 WebFetch로 직접 읽나

RISS 검색 페이지는 JS 렌더링과 세션 파라미터가 섞여 있어서, 고정된 파서 스크립트를 짜 두면
페이지 구조가 조금만 바뀌어도 조용히 깨진다. 대신 이 스킬을 실행하는 Claude가 그때그때
`WebFetch`(또는 브라우저 도구)로 검색 결과를 직접 읽고, 눈으로 구조를 확인하면서 표로
옮기는 방식을 쓴다. 이게 느려 보여도 훨씬 안정적이다 — qc-sheet 스킬이 "원본을 대충 훑고
케이스를 지어내지 말라"고 하는 것과 같은 이유다. 검색 결과 목록에 없는 정보를 추측해서
채우지 않는다.

## 검색 절차

1. 검색 URL을 만든다. 모바일 페이지(`m.riss.kr`)가 데스크톱보다 구조가 단순해서
   `WebFetch`로 읽기 쉽다.

   ```
   https://m.riss.kr/search/Search.do?query=<검색어 URL 인코딩>
   ```

   발행연도를 좁히고 싶으면 데스크톱 검색 후 URL에 붙는 `p_year1`(시작연도)·`p_year2`(끝연도)
   파라미터를 같은 방식으로 붙여본다. 파라미터가 안 먹으면 결과를 받은 뒤 연도로 직접 걸러도
   된다 — 결과 수가 그렇게 많지 않다면 이쪽이 더 확실하다.

2. `WebFetch`로 위 URL을 가져와서, "제목·저자·출처(학회지/학교)·발행연도·자료유형(학술지논문/
   학위논문/학술대회논문/단행본 등)·상세보기 링크"를 뽑아 달라고 프롬프트를 준다.

3. 결과가 한 페이지에 다 안 나오면 페이지네이션 파라미터(보통 `iStartCount` 또는
   `pageNumber`)를 바꿔가며 반복한다. 검색 결과 상단에 "총 n건"이 보통 표시되니 그걸로
   더 가져올지 판단한다.

4. 상세 링크가 상대경로거나 `control_no` 같은 식별자만 보이면, 같은 사이트의 상세보기
   URL 패턴(`m.riss.kr/search/detail/DetailView.do?...control_no=...`)으로 완성한다.
   링크를 완성 못 하면 그 행은 목록에 넣지 않는다 — `build_excel.mjs`가 링크 없는 행을
   막는다.

5. 주제와 무관해 보이는 결과(키워드는 걸렸지만 실제로 다른 주제)는 빼거나, 확실치 않으면
   포함하되 사용자에게 보고할 때 따로 짚어준다. 지어내서 판단하지 말고, 판단이 애매하면
   사용자에게 묻는다.

## RISS에서 KCI를 곁다리로 커버하기

KCI 키가 아직 없을 때는 RISS 검색 결과 중 **"국내학술논문"** 분류만 따로 세어서 KCI 대체
지표로 쓸 수 있다. RISS 통합검색 결과 화면에는 자료유형별 건수가 집계돼 보이는 경우가
많으니, 그 값을 요약 시트에 "RISS 국내학술논문(KCI 대체)"로 표기한다. 이건 정확한 KCI
등재 여부를 보장하지 않으므로, 보고할 때 반드시 "KCI 직접조회 아님"이라고 밝힌다.

## 결과를 데이터 파일로 옮기기

읽은 결과는 바로 `assets/papers.template.mjs`를 복사한 파일의 `GROUPS[].papers`에
`[제목, 저자, 출처, 연도, 유형, 링크]` 행으로 채운다. 검색어(주제) 하나당 그룹 하나가
기본이지만, 사용자가 다른 방식으로 묶고 싶다면 그쪽을 따른다.
