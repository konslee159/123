# RISS 검색 방법

RISS(학술연구정보서비스, riss.kr)는 공식 Open API가 없다. 검색 결과 페이지 자체를 읽어서
논문 정보를 뽑아야 한다.

## 우선 `scripts/search_riss.mjs`를 쓴다

```bash
node <스킬>/scripts/search_riss.mjs --query "<검색어>" --year1 2023 --year2 2026 --pages 2 --out result.json
```

**왜 `WebFetch`로 직접 읽지 않고 이 스크립트를 쓰나.** RISS 검색 결과는 페이지가 열린
뒤 JS가 실행되면서 채워지는 경우가 많다. `WebFetch`는 JS를 실행하지 않고 첫 응답만
markdown으로 바꾸는 도구라서, 검색어를 바꿔도 매번 "기본/추천 콘텐츠"만 보이는데 이게
검색이 제대로 된 것처럼 보이기 쉽다. 실제로 이 문제 때문에 "자동차 LCA"를 검색했는데
전혀 무관한 결과가 나오는 일이 있었다 — RISS가 막은 게 아니라, 애초에 검색 결과가 정적
HTML에 없었던 것이다.

`search_riss.mjs`는 헤드리스 브라우저(Playwright)로 실제 로딩이 끝나길 기다린 뒤 읽고,
**검색어가 결과 페이지에 실제로 반영됐는지 자동으로 확인한다.** 반영이 안 됐으면 —
조용히 틀린 결과를 만드는 대신 — 에러로 멈추고 실제 도착 URL과 페이지 내용을 보여준다.
이 메시지가 나오면 그 페이지의 결과는 절대 쓰지 않는다.

결과는 `title/link/year/type/rawBlockText` 형태의 JSON으로 나온다. `rawBlockText`에
저자·출처가 섞여 있으니, 그대로 데이터 파일에 옮기지 말고 한 번 읽어서 저자/출처를
분리한다 — 자동으로 분리하면 틀린 저자명이 조용히 들어갈 수 있어서 일부러 사람이
확인하게 만들었다.

### 그래도 안 될 때

- **"Chromium 실행 실패" 에러**: 이 환경에 Playwright 브라우저가 없다. `npx playwright
  install chromium`으로 설치한다 (권한/네트워크 문제로 안 되면 스크립트를 실행하는
  환경 관리자에게 문의).
- **"검색어 미반영" 에러가 계속 남**: `--dump-html snapshot.html`을 붙여서 실제로 어떤
  페이지가 왔는지 저장해서 열어본다. 흔한 원인:
  - RISS가 로그인/캡차 페이지로 리다이렉트함 → 로그인 없이 접근 가능한 검색인지 직접
    브라우저로 한 번 확인해본다.
  - 방화벽/프록시가 riss.kr 접속 자체를 막고 있음 → `curl -I https://www.riss.kr`로
    확인한다. 막혀 있으면 스크립트로는 해결이 안 되는 네트워크 문제다.
  - RISS 쪽 페이지 구조가 크게 바뀌어서 "'질의어' 검색결과" 같은 문구 자체가 없어짐 →
    `snapshot.html`을 보고 검색어 반영 여부를 확인하는 로직(`search_riss.mjs`의
    `queryReflected` 부분)을 그 페이지에 맞게 손본다.
- **결과는 나오는데 항목이 이상함**: `search_riss.mjs`는 상세보기 링크
  (`DetailView.do`) 주변 텍스트를 통째로 가져온다. 링크 근처에 광고나 관련자료 추천이
  섞여 있으면 엉뚱한 블록이 잡힐 수 있다 — `--dump-html`로 실제 구조를 보고 판단한다.

## `WebFetch`로 대체해야 할 때 (Playwright를 쓸 수 없는 환경)

이 스킬을 실행하는 환경에 Node/Playwright가 아예 없다면, Claude가 `WebFetch`로 직접
읽어야 한다. 이때는 특히 조심한다 — 방금 설명한 문제(JS 미실행으로 인한 검색어 미반영)가
그대로 재현될 수 있다.

1. `WebFetch`로 검색 URL을 가져온 뒤, **받은 내용에 검색어(또는 검색어를 이루는 단어들)가
   실제로 포함돼 있는지부터 확인한다.** 없으면 그 결과는 버리고, "이 환경에서는 RISS를
   직접 읽을 수 없다"고 사용자에게 솔직히 보고한다 — 무관한 내용을 논문 목록인 것처럼
   담지 않는다.
2. 포함돼 있다면 제목·저자·출처(학회지/학교)·발행연도·자료유형·상세보기 링크를 뽑는다.
3. 결과가 한 페이지에 다 안 나오면 페이지네이션 파라미터(`pageNumber` 등)를 바꿔가며
   반복한다.
4. 상세 링크가 상대경로거나 식별자만 보이면 `DetailView.do?...control_no=...` 형태의
   전체 URL로 완성한다. 완성 못 하면 그 행은 목록에 넣지 않는다.

## RISS에서 KCI를 곁다리로 커버하기

KCI 키가 아직 없을 때는 RISS 검색 결과 중 **"국내학술논문"** 분류만 따로 세어서 KCI 대체
지표로 쓸 수 있다. 정확한 KCI 등재 여부를 보장하지 않으므로, 보고할 때 반드시 "KCI
직접조회 아님"이라고 밝힌다.

## 결과를 데이터 파일로 옮기기

정리된 결과는 `assets/papers.template.mjs`를 복사한 파일의 `GROUPS[].papers`에
`[제목, 저자, 출처, 연도, 유형, 링크]` 행으로 채운다. 검색어(주제) 하나당 그룹 하나가
기본이지만, 사용자가 다른 방식으로 묶고 싶다면 그쪽을 따른다.
