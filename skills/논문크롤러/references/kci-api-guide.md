# KCI Open API 키 발급 방법

KCI(한국학술지인용색인) 논문 데이터를 API로 받으려면 인증키(서비스키)가 있어야 한다.
두 가지 경로가 있는데, **공공데이터포털(data.go.kr) 경로를 권장한다** — 국내에서 가장
표준화된 절차라 승인이 빠르고(대부분 즉시~1~2시간 내 자동승인), 신청 화면과 절차가 잘 문서화돼 있다.

> 이 문서는 data.go.kr의 일반적인 활용신청 절차(공공 오픈API 공통 절차)를 바탕으로 작성했다.
> 화면 구성은 포털 개편으로 바뀔 수 있으니, 아래 단계에서 메뉴 이름이 조금 다르면 "활용신청" /
> "오픈API" 관련 메뉴를 찾으면 된다.

## 방법 1 — 공공데이터포털(data.go.kr) 경유 (추천)

1. [data.go.kr](https://www.data.go.kr) 접속 후 회원가입 → 로그인.
2. 검색창에 **"KCI 논문정보"** 또는 **"한국연구재단 KCI"** 로 검색.
   - `한국연구재단_KCI 논문정보서비스` (논문 제목·저자·초록·발행연도 등 검색) 를 찾는다.
   - 목적에 따라 `한국연구재단_KCI 학술지정보서비스`(저널 자체 정보)도 함께 신청해두면 좋다.
3. 데이터셋 상세 페이지에서 **"활용신청"** 버튼 클릭.
4. 활용목적을 간단히 적는다 (예: "선행연구 조사용 개인 연구 목적"). 시스템 유형은 보통
   "일반" 또는 "개발계정"을 선택하면 된다.
5. 신청 완료 후 **마이페이지 → 오픈API → 개발계정(또는 활용신청 현황)** 에서 승인 상태를 확인한다.
   - 대부분의 공공데이터는 자동승인이라 몇 분~1~2시간 내 승인된다. 그래도 안 되면 하루 정도
     걸릴 수 있다.
6. 승인되면 마이페이지에 **인증키(서비스키, `serviceKey`)** 가 표시된다. 일반 인증키 / 정제
   인증키 두 가지가 있을 수 있는데, 보통은 **일반 인증키(Encoding)** 를 그대로 쓰면 된다.
7. 같은 페이지에서 **활용가이드(요청변수·응답 항목이 정리된 문서, 보통 PDF/HWP)** 를
   내려받을 수 있다 — 요청 파라미터 이름(`title`, `author` 등)과 응답 태그 이름이 데이터셋마다
   조금씩 다르니, 실제 스크립트를 돌리기 전에 이 문서를 한 번 보는 걸 권한다.

발급받은 키는 이렇게 쓴다.

```bash
node scripts/search_kci.mjs --key "<발급받은 인증키>" --query "배터리 LCA" --dump
```

`--dump`로 원본 응답을 한 번 찍어보고, 태그 이름이 `scripts/search_kci.mjs`의
`FIELD_CANDIDATES`와 다르면 그 목록에 실제 태그 이름을 추가한다.

## 방법 2 — KCI 포털(kci.go.kr) 자체 발급

KCI가 [자체 Open API 포털](https://www.kci.go.kr/kciportal/po/openapi/openApiConnSearch.kci)도
운영한다. 여기서 발급받은 키는 API 요청 주소가 다를 수 있으니 `search_kci.mjs`의 `--base`
옵션으로 엔드포인트를 바꿔서 쓴다.

1. kci.go.kr 접속 → 로그인(회원가입 필요).
2. 상단 메뉴에서 **오픈API → 인증키 신청/관리** 로 이동.
3. 신청서 작성 후 제출. **승인까지 시간이 더 걸리거나 담당자 확인이 필요할 수 있다** (문의:
   042-869-6674/6675, kciadmin@nrf.re.kr). 급하면 방법 1을 먼저 시도하는 게 낫다.
4. 승인되면 인증키와 API 명세서를 받는다.

## 키가 아직 없거나 승인 대기 중이라면

이 스킬은 KCI 키가 없어도 동작한다 — **RISS 검색으로 대체**하면 된다. RISS의 "국내학술논문"
분류가 KCI 등재지를 상당 부분 포함하므로, 키 발급을 기다리는 동안에도 조사를 시작할 수 있다.
SKILL.md의 "KCI 키가 없을 때" 절 참고.

## 방법 1과 2는 요청 형식이 다르다

- **방법 1 (data.go.kr)**: 보통 `serviceKey`, `title` 같은 파라미터 이름을 쓴다.
  `search_kci.mjs`의 기본값이 이쪽이다.
- **방법 2 (kci.go.kr 자체 포털)**: 파라미터 이름이 다를 수 있다 (예: `key`). 활용가이드
  문서에 나온 실제 요청 URL을 보고 `search_kci.mjs`를 이렇게 조정한다.

  ```bash
  node scripts/search_kci.mjs --key "<발급받은 키>" --query "배터리 LCA" \
    --base "<가이드에 적힌 요청 주소>" --auth-param key --query-param title --dump
  ```

**주의: 활용가이드 문서의 예시 URL에 있는 키(`key=00000001` 같은 값)는 진짜 키가
아니라 문서용 샘플이다.** 실제 키는 신청 승인 후 마이페이지에서 확인하는, 보통 20자
이상의 영문/숫자 조합이다. `search_kci.mjs`는 짧거나 0으로만 된 키를 넣으면 경고를
띄운다.

## 흔한 오류

- `resultCode`가 `00`/`0`이 아닌 응답: 대부분 (1) 키가 아직 승인 대기중, (2) 파라미터 이름이
  이 데이터셋과 다름, (3) 신청한 데이터셋과 요청 주소(`--base`)가 다른 경우다.
- 키를 발급받은 직후 몇 분간은 401/오류가 날 수 있다 — 시스템 반영에 시간이 걸린다.
