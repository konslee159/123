# 논문크롤러

주제를 주면 국내 논문 데이터베이스(RISS, KCI)에서 관련 논문을 찾아 엑셀 한 장으로
정리해준다. 목적은 선행연구 조사·동향 파악에 드는 반복 작업(사이트마다 검색하고, 결과를
하나씩 복사해서 표로 옮기는 일)을 줄이는 것이다.

**엑셀을 직접 만들지 않는다.** 검색한 논문을 데이터 파일(`.mjs`) 하나에 정리해 넣으면
스크립트가 엑셀을 만들고 검증한다. 이유는 "왜 이렇게 하나"에 있다.

## 준비

스크립트는 이 스킬 폴더의 `node_modules`를 쓴다. 처음 한 번만:

```bash
npm install --prefix <이 스킬 폴더>
```

Node.js가 필요하다.

## 절차

### 1단계 — 검색 범위를 확정한다

사용자에게 주제/키워드를 확인한다. 검색어가 여러 개로 쪼개질 수 있는 주제라면
(예: "자동차·배터리·전기전자 분야의 LCA 논문") 검색어별로 그룹을 나눌지 먼저 확인하는 게
좋다 — 그룹마다 엑셀 시트가 하나씩 생긴다.

발행연도 범위, 원하는 자료유형(학술지논문만? 학위논문도?), 대략 몇 건 정도를 원하는지도
이때 확인한다. 확인 없이 마음대로 정하면 나중에 범위를 다시 잡아야 한다.

### 2단계 — RISS에서 검색한다

`references/riss-search-guide.md`를 읽고 그대로 따른다. 요점만 말하면: RISS는 공식
API가 없으므로 `WebFetch`로 검색 결과 페이지를 직접 읽어서 제목·저자·출처·연도·유형·
상세링크를 뽑는다. 페이지를 대충 훑고 그럴듯한 논문을 지어내면 안 된다 — 실제로 검색
결과에 있는 것만 담는다.

### 3단계 — KCI에서 검색한다 (키가 있으면)

사용자가 KCI Open API 키를 가지고 있으면:

```bash
node <스킬>/scripts/search_kci.mjs --key "<서비스키>" --query "<검색어>" --dump
```

먼저 `--dump`로 원본 응답을 한 번 보고 태그 이름이 예상과 맞는지 확인한 뒤, `--dump`
없이 다시 돌려서 파싱된 결과를 받는다. 키가 없다고 하면 **`references/kci-api-guide.md`를
안내한다** — data.go.kr에서 발급받는 절차가 단계별로 정리돼 있다.

**KCI 키가 아직 없거나 발급을 기다리는 중이면 RISS만으로 진행한다.** RISS의
"국내학술논문" 분류가 KCI 등재지를 상당 부분 포함하므로 대체 지표로 쓸 수 있다. 이 경우
최종 보고에 "KCI는 직접 조회하지 못했고 RISS 국내학술논문 결과로 대체함"이라고 반드시
밝힌다 — 확인 안 된 걸 확인된 것처럼 보고하지 않는다.

### 4단계 — 데이터 파일을 채운다

`assets/papers.template.mjs`를 작업 폴더로 복사해서 채운다. 한 행은
`[제목, 저자, 출처, 연도, 유형, 링크]` 이다. 파일 안 주석에 각 항목 규칙이 있다.

지켜야 할 것 세 가지:

- **제목과 링크는 절대 비우지 않는다.** 링크를 못 찾은 논문은 목록에서 뺀다 — 나중에
  사용자가 클릭해서 원문을 확인할 수 있어야 엑셀의 존재 이유가 있다.
- RISS와 KCI 양쪽에서 같은 논문이 잡힐 수 있다. 그대로 두면 검증 단계에서 중복으로
  걸리니, 발견 즉시 하나만 남긴다.
- 주제와 관련성이 낮아 보이는 논문은 애매하면 사용자에게 포함 여부를 물어본다. 마음대로
  빼거나 넣지 않는다.

### 5단계 — 만들고 검증한다

```bash
node <스킬>/scripts/build_excel.mjs  <데이터 파일>
node <스킬>/scripts/verify_excel.mjs <데이터 파일>
```

`build_excel.mjs`가 시트별 표와 "0_요약" 시트(그룹별 건수 합계)를 만든다. 링크 컬럼은
클릭하면 원문으로 가는 하이퍼링크로 들어간다.

`verify_excel.mjs`는 빈 제목/링크, 이상한 연도 값, 시트 간 중복 논문, 시트 이름 충돌을
잡는다. **걸린 건 반드시 고치고 다시 돌린다.**

### 6단계 — 결과를 보고한다

파일 경로와 함께 이것들을 전한다.

- 그룹(시트)별 건수와 전체 건수
- KCI를 실제로 조회했는지, RISS로 대체했는지
- 관련성이 애매해서 포함 여부를 사용자 판단에 맡긴 논문이 있다면 그 목록
- 검색에서 빠졌을 수 있는 부분(예: 페이지네이션을 끝까지 다 못 봤다면 그 사실)

## 왜 이렇게 하나

**엑셀을 직접 만들지 않고 데이터 파일을 거치는 이유.** 논문을 하나 추가하거나 빼면 번호가
전부 밀린다. 데이터 파일을 거치면 빌드할 때마다 번호와 요약 건수를 다시 계산하므로
손으로 옮겨적다 생기는 오류가 없다. 그래서 나중에 논문을 추가/삭제할 때도 엑셀이 아니라
데이터 파일을 고친다.

**RISS를 스크립트로 자동 파싱하지 않고 Claude가 직접 읽는 이유.** RISS는 공식 API가
없어서 페이지 구조에 의존해야 하는데, 고정 파서는 페이지가 조금만 바뀌어도 조용히 틀린
값을 뱉는다. 매번 직접 읽으면 이상한 결과를 그 자리에서 알아챌 수 있다.

**링크가 필수인 이유.** 논문 목록의 가치는 "나중에 클릭해서 원문을 확인할 수 있다"는
데 있다. 링크 없는 행은 제목만 있는 메모와 다를 게 없다.

## 프로젝트 규칙이 있으면 그게 우선

작업 폴더에 `AGENTS.md`나 `CLAUDE.md`가 있고 결과물 양식이 정의돼 있으면 먼저 읽고
따른다. 사용자가 기존 엑셀 샘플이나 템플릿을 주면 이 스킬의 기본 양식보다 그쪽을
우선한다.

이 스킬이 고정하는 건 절차(검색 → 정리 → 검증)이지, 결과물의 세부 양식이 아니다.

## 파일

```
논문크롤러/
├── scripts/
│   ├── build_excel.mjs   데이터 파일 → 엑셀
│   ├── verify_excel.mjs  산출물 검증
│   └── search_kci.mjs    KCI Open API 검색
├── references/
│   ├── riss-search-guide.md  RISS 검색 방법 (2단계 전에 읽는다)
│   └── kci-api-guide.md      KCI Open API 키 발급 방법
└── assets/
    └── papers.template.mjs   데이터 파일 템플릿
```
